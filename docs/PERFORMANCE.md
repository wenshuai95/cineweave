# 表演编排（v1.23）

给一段剧情，让文字模型输出**节拍表**（谁、什么时候、做什么动作、怎么移动、朝向谁），
再由本机把它翻译成角色动作 + 走位关键帧。**只改表演，不改机位和镜头。**

## 使用

1. 进入 3D 导演台，时间轴工具条 → **表演编排**。
2. 写一段剧情（只写表演与走位，不写机位），勾选参与角色（角色需已加载动作）。
3. 点「生成编排」：本机文字模型输出节拍表 → 自动校验 → 本地挑动作/排时间/定走位。
4. 预览节拍列表（含每个节拍用到的真实片段名、缺失动作、警告）。
5. 点「采用」写回工程；可 ⌘Z 撤销。机位与镜头编排保持原样。

## 节拍表契约

```json
{"beats":[{"start":0,"end":1.6,"character":"角色ID或名称","action":"sit",
           "move":"hold|toward|away|left|right|up|down","face":"other|front|back|none",
           "distance":1.2,"note":"可选"}],"note":"整体说明"}
```

- 动作标签：`idle / walk / run / sit / cast / attack / hit / death / jump / crouch / interact / talk / dance`
- 常见同义词会被归一（如「倒地」→death、「施法」→cast）；无法归一才拒绝。
- 同一角色节拍不能重叠；每个节拍 0.2 秒以上；最多 40 段。
- 模型输出被拒时，界面会带错误信息**自动重试一次**；仍失败则不采用。

## 动作检索

- 每个片段的英文名先归类（`RT_Spell_Simple_Idle_Loop` → cast，`Adult_Walk` → walk，`坐地施法` → cast）。
- 优先选规范片段（`Idle_Loop`、`Walk_Loop`、`Sitting_Idle_Loop`、`Spell_Simple_Idle_Loop`），
  避免僵尸/火把/TPose/躺下这类变体；循环片段可拉长，非循环按节拍时长调速度（0.3–2.5 倍）。
- 找不到对应动作时**不编造**：列出「缺动作」，该角色的这一段保持原表演。

## 实测（2026-10-19，DeepSeek deepseek-flash）

- 剧情：玉印片段（坠落/后退/结印/玉印下坠/男修救人/升空/巨妖掷印），24 秒
- 角色：女修（109 段动作）+ 男修（109 段动作）
- 模型输出 **15 个节拍**；本地编排 15 段、**缺动作 0**、无警告
- 生成到落工程约数秒；镜头/机位零改动（测试断言）

## 接口

客户端走已有 `/api/ai/text/generate`，`kind: "performance-plan"`：
`{kind, prompt, duration, characters:[{id,name,clips:[{name,duration}]}]}`，
返回 `{beats:[...], note}`（服务端校验后才返回）。

## 已知边界

- 模型只负责「节拍级」表演，不处理细腻情绪、视线、接触；这些仍需人工在导演台微调。
- 动作质量取决于角色片段库；重定向后的 `RT_` 片段可用，但脚底滑步需人工修。
- 走位按节拍做线性/平滑位移，不做寻路与避障；两个角色可能穿插。
- 生成的朝向依赖模型原生朝向约定（当前按 glTF 默认面向 -Z 处理）。

## 深度思考（v1.23.1）

表演编排等规划类调用默认开启 DeepSeek 深度思考，并预留 +6000 token 思考预算。
同一剧情实测：关闭思考 3.2 秒 / 18 个节拍；开启思考 9.5–23 秒 / 26 个节拍，
动作顺序更贴剧情（先倒地、再坐、再结印）。详见 [文字模型说明](TEXT-MODEL.md)。
