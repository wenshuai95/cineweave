# 文字模型：为什么应用里和 Agent 里感觉不一样（v1.23.1）

## 结论先说

应用里的模型调用是**单次、无工具、带严格 JSON 约束**的；Agent 是**多轮、可用工具、能自己检查再重试**的。
同一个 `deepseek-flash`，在两种壳里表现本来就会差一截。

v1.23.1 之前还有一个硬伤：造梦工坊对 DeepSeek 官方接口**写死了关闭深度思考**（`thinking: disabled`），
而 Agent 侧是带推理的。这次已经改成默认开启。

## 实测对比（同一剧情、同一提示词、24 秒节拍表任务）

| 配置 | 耗时 | 节拍数 | 结果 |
|---|---|---|---|
| deepseek-flash · 关闭思考（旧行为） | 3.2s | 18 | 可用，顺序偶有跳跃 |
| deepseek-flash · 开启思考（v1.23.1） | 9.5–23s | **26** | 倒地→坐→结印顺序更贴剧情，缺动作 0 |
| deepseek-v4-pro · 开启思考 | 66s | 15 | 质量不差但更粗、更慢，思考占满 token 预算 |

## 这次改了什么

1. **默认开启深度思考**：除「测试连接」外的所有调用（对话、剧本、分镜、资产、白模导演、表演编排）。
2. **给思考留 token 预算**：`max_tokens` 额外 +6000，避免思考占满导致正文为空。
3. **表演编排被拒自动重试一次**：把校验错误回传给模型，让它自己修正。
4. 动作标签同义词归一（「倒地」→death 等），减少整份方案作废。

## 仍然存在的结构差距

| 能力 | Agent（如 DeepSeek Harness） | 应用内文字模型 |
|---|---|---|
| 多轮工具调用 | 有 | 无 |
| 自行检查/重试 | 多轮循环 | 最多一次自动重试 |
| 上下文 | 完整会话 + 工具结果 | 单次请求里截断后的工程摘要 |
| 规划深度 | 可拆步骤、可回读 | 一次成稿 |
| 延迟 | 可接受 | 开启思考后 10–60 秒 |

所以：**重要方案建议仍可以让我来做；日常微调、批量生成，用应用内的编排更快。**

## 可调项

- 模型 ID：设置 → API 服务 → 文字模型；`deepseek-flash`（快）/ `deepseek-v4-pro`（慢、复杂任务可选）。
- 思考开关目前按上文策略写死在 `text-writing.mjs`，后续可做成设置项。
- 测试连接仍走 `/models`，不产生思考费用。
